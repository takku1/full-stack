No UI, remote service, scheduler, or database replacement. Keep the CLI responsible for file selection, command outcome and reporting; parsing/validation produces records or diagnostic entries; the existing adapter owns persistence. These responsibilities need not become crates or services.

Define required observable semantics before writes: identify rows by logical CSV record number (not merely physical line, since quoted fields may span lines); report every rejected record with a reason, avoid unnecessary sensitive field content, and report accepted/rejected/write outcome totals. The record schema and validation rules are not supplied and must come from the existing adapter/domain contract. Fatal input failures such as unreadable input or unrecoverable CSV structure produce a clear diagnostic and a nonzero exit. A malformed row may be recoverable only if the parser can reliably locate the next record; no silent skips. Do not claim imported counts before persistence is confirmed.

Critical investigation: inspect adapter contracts, implementation, and targeted tests for batch atomicity, commit acknowledgment, partial failure details, stable record identity, duplicate handling, and failure after commit. Exercise a middle-of-batch failure and a lost acknowledgment against a safe test store where feasible. Determine whether writes are all-or-none, individually acknowledged, or potentially ambiguous. This evidence unlocks retry policy and whether a partial-success import is implementable without duplicate effects. Do not enable automatic retries until those guarantees are known.

Also settle the desired command exit status for recoverable row rejection and storage failure, whether valid records may be committed when other rows are rejected, and cancellation behavior. These decisions affect the promised outcome and must be explicit in the subject roadmap. All-or-none storage does not by itself mean the user wants the entire file rejected for one invalid row. If whole-file validation is chosen, staging/re-reading must account for input changes; bounded streaming instead needs explicitly accepted partial-write semantics.
