# Local notes design and handoff

Current state at handoff: empty isolated trial directory. Target: local HTML application with committed SQLite notes surviving process restart. User fixes Python standard library, SQLite, localhost, forms, and success redirects. No research claims or additional dependencies. Authentication and deployment are excluded by request.

Requirements originating in INPUT.md: R1 add/list/delete independent notes with durable identity; R2 reject blank title/body with visible HTTP 400; R3 escape stored text; R4 absent delete gives visible HTTP 404; R5 forms and 303 redirects; R6 localhost-only lifecycle and restart persistence. R7 is the later title-length change, applied after initial verification. R8 is the final documentation-only label change.

Application policy and persistence live in notes.py: create normalizes surrounding whitespace, validates fields before writing, and returns generated integer identity; list returns stored records in ascending identity order; delete commits exactly one existing identity or raises MissingNote. SQLite is durable state authority; operations open and close their own connection, use bound parameters and transactions. No schema migration is needed for R7: existing titles remain readable/deletable, while only new writes receive the new policy. Reversal removes that validation without changing data.

HTTP/presentation lives in app.py: GET / lists notes and renders add/delete forms; POST /notes accepts URL-encoded title/body; POST /notes/{positive integer}/delete deletes one. Success is 303 Location: / after database commit. Validation errors render a complete page with explanation and status 400. Missing identities render 404. All persisted and reflected values pass through html.escape. Unknown paths return 404. No editing, search, concurrent multi-user feature, or production server design is in scope.

The main process creates the schema then binds 127.0.0.1 only, prints its actual selected port, serves synchronously, and closes on KeyboardInterrupt. The database path is explicit; default is local notes.sqlite3. A sequential server keeps transactions bounded for this small local demo. A crash after commit before redirect may leave a successful creation without acknowledgment; automatic retries are not implemented and resubmission may create a new note. No performance target or broader security guarantee is asserted.

Integration order and closure evidence are recorded in ROADMAP.md: policy/storage, HTTP/forms, real subprocess tests, follow-up policy change with regression run, documentation label edit. tests.py must send real HTTP requests with redirects disabled to inspect statuses, inspect displayed escaping and error explanations, exercise independent deletions and restart a server with the same SQLite file. Browser interaction is conditional on an available tool; no browser tool was exposed by discovery.
