# Design: image-thumbnail loading for a no_std Rust desktop

**Grounding.** The working directory holds only the [skill] skill files. It has no Rust sources, no manifest, and no copy of the image-source or rendering contracts. I read no subject code and wrote no files. This design stays in chat, and I did not browse.

**Assumptions.** If an assumption is false, the cost is the one given.
- The image-source and rendering contracts exist as you describe, and I have not seen them. If either differs from what I use below, the loader's two edges must be re-matched. Only the edge adapters change.
- The target has some memory strategy, either a global allocator or fixed buffers. I don't know which. If it has neither, the decode path needs a fixed-buffer design.

## 1. Scope
- **Outcome:** a thumbnail is produced from bytes supplied by the settled image source and handed to the settled rendering contract.
- **Work IDs:**
  - T1: decoder-neutral loader core
  - T2: thumbnail budget policy
  - T3: failure, cancel, retry
  - T4: cache authority
  - T5: library adapter
  - T6: format support list
  - T7: real-decode verification
- **Exclusions:**
  - Changing the image-source or rendering contracts.
  - Choosing, vendoring, or installing the library.
  - Full-size image display.
  - Any claim about the library's formats or allocation needs.
- **Deferred enhancements:** progressive loading, prefetching, and disk cache. They are not required now.

## 2. Ownership and contracts
| Concern | Authority | Notes |
|---|---|---|
| Source bytes | The settled image source | The loader consumes them and never redefines them. |
| Pixel hand-off | The settled rendering contract | The loader emits what that contract accepts. |
| Decode capability | A new `ThumbnailDecoder` seam owned by the loader | The seam is the only place a library appears. |
| Memory budget | The loader's policy (T2) | The decoder must fit it. It cannot negotiate it. |
| Thumbnail cache | The loader (T4) | The cache holds derived data only. The source stays authoritative. |

Trigger-to-result flow:
1. A thumbnail is requested for a source item.
2. The loader checks the cache. On a hit it hands the thumbnail to rendering.
3. On a miss it fetches bytes from the source and passes them with a budget to the decoder.
4. It downsizes the result to the thumbnail size and stores it in the cache.
5. It hands the thumbnail to rendering.

Failure paths:
- **Unsupported or corrupt data:** return a typed error and render a placeholder. The error is not cached as success.
- **Over budget:** return a typed `OverBudget` error. Do not retry it automatically.
- **Cancellation:** the caller can cancel before decode. In-flight decode finishes or aborts, and its result is discarded.
- **Retry:** retry is allowed only for source fetch errors, with a bounded count.
- **Recovery:** a failed item stays retryable on the next request.

Consumer and provider matching:
- The loader's input assumption is "bytes plus an item identity". That is unresolved until the source contract is read.
- The loader's output assumption is "a pixel buffer in the rendering contract's layout". That is also unresolved until the rendering contract is read.
- The library's guarantees are unknown, so they are an explicit unresolved condition.

## 3. Choices
- **Seam over direct coupling (chosen).** The seam lets T1–T4 proceed without library facts. The cost is one indirection. Revisit it if the library turns out to need a different call shape.
- **Alternatives for the decoder (open):**
  - The proposed library.
  - Per-format minimal decoders.
  - A fixed-format-only decoder.
  - There is no evidence to choose among them, so the choice is open.
- **Fit gaps (all unverified):**
  - supported formats
  - whether it needs `alloc`
  - peak memory per decode
  - streaming or whole-buffer input
  - `no_std` feature flags
  - license
- **Revisit condition:** when the library's documentation becomes available, or when you choose another decoder.

Choosing and adopting the library is a costly-to-reverse commitment, and it is **not authorized**. I did not ask interactively because this session is non-interactive. Everything that depends on it is marked conditional below.

## 4. Increments

**Unexecuted checks:** none were run. Every check above is a plan only.
